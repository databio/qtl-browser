# The TOPCHeF browser on the version 2 store

## What has to change, and why it is one piece of work

The two apps share `src/lib` by copy and the copies are identical today (`diff -rq ui-topchef/src
ui/src` is empty), so the reader is written once, in `ui-topchef/`, and mirrored to `ui/` after;
the general app's own divergence (a collection chooser, no default) is a later plan. Three layers
of the reader are bound to version 1, and every page sits on all three:

- **Opening the store** (`lib/store.ts`). `store.json`'s `experiments` is read as an array of ids
  (`.includes` throws on the version 2 map), one `experiments/topchef.json` is opened, and its
  `results[]`, `trans` and `gwas` fields are the whole data model. Version 2 has five experiments
  for TOPCHeF, each with its own index parts, hits and ordinal space, and a `collection` field
  naming a content-addressed document that carries the citation.
- **Decoding objects** (`lib/store-decode.ts`). The results block is read as `QGB0` with
  interleaved `(nlp, se)` pairs and the slope rebuilt through the inverse t with the experiment's
  `dof`; the trans frame as `QTT2` with the SE derived the same way; the GWAS block as the 21-byte
  lossless row. Version 2 stores `nlp`, `beta` and `se` in every kind, columnar in the block, with
  credible-set sections in the trans frame and GWAS block, and `FORMAT_VERSION` is a hard check.
- **Assembling pages** (`gene.ts`, `gene-index.ts`, `trans.ts`, `variant.ts`, `cis-scan.ts`,
  `coloc-abf.ts`, `rounding.ts`, the About and Home routes). A gene page reads one index part for
  both types and both scopes; a variant page reads one hits file holding leads, credible sets and
  trans records; `partOfOrd` resolves an ordinal in one shared space; coloc forms `z` from the
  rebuilt slope; the rounding note reads the five version 1 precision keys.

The live site is broken on every gene page since the significance deploy (the bucket's index
still carries `p_perm`), and the version 2 release is what fixes it, so this work is on the path
to the fix rather than beside it.

## Decisions & ownership

|---|---|---|---|
| D1 | **How the TOPCHeF app pins its collection**: config names one anchor experiment, `VITE_COLLECTION_OF=topchef_ge_cis`, and the app takes every experiment in `store.json` sharing that experiment's `collection` value as the study. The GWAS is named separately, `VITE_GWAS=dcm_jurgens2024_biobanks`, since it is in its own collection (experiment-model D3, D7) | **user-owned, surfaced** | The alternatives are worse: pinning the collection *digest* breaks the build every time a title or DOI is edited, since the digest is of the document's bytes; pinning by title is string matching on prose; listing all four QTL ids is four things to keep in step with the pipeline's naming. Naming one member and deriving the rest costs nothing and survives metadata edits. It forces: the app refuses to open if the anchor is absent or its siblings disagree on `kind`/`phenotype_type` pairs it needs |
| D2 | **The gene page's two tabs stay bound to `ge` and `leafcutter`** (`EQTL_TYPE`, `SQTL_TYPE`), resolved to the collection's `qtl_cis` and `qtl_trans` experiments of each type | AI-owned, defended | This is the single-study app; the general app is where phenotype types become data. A collection with no `leafcutter` scans renders the sQTL tab unavailable, as a missing trans object does today |
| D3 | **A gene page reads one index part per QTL experiment it shows**: up to four parts (cis and trans for each type), in parallel, keyed by the gene's chromosome; the trans experiments' `search_index_unplaced` part is read only when a phenotype is not found under the chromosome | AI-owned, defended | Measured genome-wide after the split: chr1 cis parts 60 KB + 199 KB (against 322 KB before), trans parts 15 KB and 90 KB at the median. | D4 | **A variant page reads one hits file per QTL experiment** on the variant's chromosome, four frame tables and up to four frames, and joins them; each record's `ord` resolves in *its own* experiment's index | AI-owned, defended | The ordinal space is per experiment by design (D10a). `partOfOrd` and `phenotypesByOrd` take the experiment. Cost: four range reads where there was one; the frame tables are ~3 KB each and cached per session |
| D5 | **The slope is gone from the reader.** `ResultBlock.beta` replaces `slope`; `negative` and `tFromNlp` leave the hot path; `transSe` is deleted; coloc forms `z = beta / se` on both sides. `dof` is shown as provenance and used for one thing only: the trans table's `r2 = t² / (t² + dof)` with `t = beta / se`, NaN without a dof | AI-owned, defended | This is the point of version 2 (v2 plan D1). `tFromNlp` stays in the file for `r2` and for nothing else |
| D6 | **The speculative-pointer machinery stays, extended.** After `store.json` the app knows the anchor's siblings and their catalog and annotation ids only from the documents, so a remembered set of ids (from the last open) is fetched in the same wave as `store.json`, and a wrong guess costs the discarded requests | AI-owned, default | Experiment-model D23 deletes it for the general app, where nothing loads before a choice. The TOPCHeF app loads its study on first paint, so the second round trip it saves is real. Challenge if the simplicity is worth more than one round trip |
| D7 | **Credible sets in trans frames and GWAS blocks are decoded and checked, not shown** | AI-owned, defended | No source in hand has any; the decoders must accept the section so a store that has them opens, and a UI for them is work with no data to drive it |
| D8 | **The rounding note and the About page read the version 2 `precision` block**: the worst `theoretical_limit` over the cis scans for the cis note, over the trans scans for the trans note, and the GWAS's own for the GWAS, each quantity in its own unit (`neglog10p` absolute, `beta_over_se` in SE units, `se_rel` relative). The About page's citations come from the collection documents | AI-owned, defended | The five version 1 keys no longer exist. The GWAS is no longer lossless and the page must say so |
| D9 | **Coloc's priors stay where they are**, a constant in `coloc-abf.ts` per app, with the `sdY = 1` assumption documented there and on the About page | AI-owned, defended | Experiment-model D14 said "deployment config". A per-app source constant *is* per-deployment config in a two-app repo; a build-time environment variable parsed as JSON would be ceremony. Revisit when a deployment needs different priors from its code |
| D10 | **Acceptance is the Python decoders and the genome-wide local store.** `scripts/store_reference.py` and `scripts/store-check.ts` are ported to version 2 and run against `data/derived/store-genome-v2`; the smoke suites and `bench/pages.json` gain entries for that store. Sam runs the dev server and the browser suites; the agent runs `npx tsc -b` and `npm run store-check` | **user-owned, surfaced** (follows the standing rule) | The subset store misled three estimates in a row; the reference check is what proves a decoder rather than a rendered page. `QTL_DATA_DIR=data/derived/store-genome-v2 VITE_DATA_BASE= npm run dev` serves it with Range support |
| D11 | **`FORMAT_VERSION` 2, hard.** A version 1 store refuses to open with the same message the current build shows for a version 2 one | AI-owned, defended | Reading both would mean carrying both decoders in the bundle for a store that is being replaced by this release |

## What this changes elsewhere

- **The bundle's data model** changes shape: `Store` holds `cis: Map<type, CisExperiment>`,
  `trans: Map<type, TransExperiment>`, `gwas: GwasExperiment | null`, `collection` and
  `gwasCollection` documents, with `hasTrans`/`hasGwas` derived. Every `s.experiment.*` and
  `s.results.get(type)` access in the five lib modules and three routes changes.
- **Request counts per page** go up: a gene page from one index part to up to four, a variant
  page from one hits table and frame to up to four of each. All parallel. The bench harness
  measures it; the pre-change baseline is in `bench/results/`.
- **`scripts/store_reference.py`** reads the version 2 documents; its output schema changes, so
  old reference files are unusable with the new check.
- **The smoke suites** (`bench/smoke_*.mjs`) read `experiments/topchef.json` and `results[]`
  directly and must read the five documents instead; the chr21/22 page ids they use exist in the
  genome-wide store too, so the genes stay.
- **The About page's prose** about the GWAS being lossless, and the "Values are rounded" tooltip's
  wording, change to what the precision block says; the DCM citation moves from prose into data.
- **The deploy workflows** are untouched; `.env.production` gains `VITE_COLLECTION_OF` and
  `VITE_GWAS`. A deploy before the bucket holds the version 2 store would show the version-mismatch
  message on every page, which is why upload precedes deploy in the release order.
- **`ui/`** diverges from `ui-topchef/` until D12 is done.
- **The live site** stays as it is until the release: home page up, gene pages spinning.

## Steps

1. `store-decode.ts`: `FORMAT_VERSION = 2`; the results block (`QGB2`, 72-byte header, columnar
   `nlp`/`beta`/`se`, `flags`); `scanBlockRow` and `blockHeader` on the new offsets; the trans frame
   (`QTT3`, se scales, `n_cs`, records); the GWAS block (48-byte header, quantized triple, records);
   `transSe` deleted. Hits, variants, indexes, lookup, bins unchanged.
2. `store.ts`: the document types (`StoreDoc` map, `CollectionDoc`, `CisExperiment`,
   `TransExperiment`, `GwasExperiment`), `openStore` with D1's selection and D6's guessing, the
   per-experiment part readers, `resultsFile`/`transFile`/`gwasFile`/`hitsFile` by experiment,
   `getStoreInfo` with counts, sources from the collection documents and the new precision shape.
3. `gene-index.ts`: parts per experiment, `partOfOrd`/`phenotypesByOrd` per experiment, the trans
   experiments' unplaced part, `transPhenotypesOfGene` from the trans experiments.
4. `gene.ts`, `trans.ts`, `variant.ts`, `cis-scan.ts`, `coloc-abf.ts`: `beta` for `slope`, stored se,
   the GWAS columns, hits per experiment, `r2` from `beta / se`.
5. `rounding.ts`, `rounding-note.tsx`, `About.tsx`, `Home.tsx`: the precision block, the citations,
   the GWAS no longer lossless.
6. `scripts/store_reference.py` and `scripts/store-check.ts` for version 2; the smoke suites; new
   `bench/pages.json` entries for the genome-wide local store. `npx tsc -b` and `npm run store-check`
   clean; the browser suites and the bench are Sam's to run.
7. Mirror to `ui/` (D12), then the general app's own plan.

## Implementation log

Steps 1 to 6 are done against `data/derived/store-genome-v2`, uncommitted on `feat/qtlstore-v2`.
Step 7 waits on Sam's browser run; the upload is gated on it.

**Offline checks, all green.** `npx tsc -b` clean; `npm run lint` only the pre-existing
LocusPlot and Variant warnings; `VITE_DATA_BASE= npm run build` builds. The decoder round trip
runs 15 s (Python) plus 25 s (TS) on the genome-wide store: every site of the 23 variants files
and every record of the 92 hits files and the rsID index summed against the Python decoders with
sampled pages, frames and blocks compared in full; 133 trans frames, 122 cis blocks (64 with
credible sets), 13 GWAS windows plus all 12,494,731 GWAS rows summed per chromosome; 93 search
index parts; the collection document; the coloc table. The only tolerance is the standard error,
`exp()` of its code, where V8 sits one ulp from numpy (2.2e-16); every other value is bit-identical.

**What changed in the reference and the suites.** The old reference dumped the chr21/22 store
whole; genome-wide that is gigabytes, so `store_reference.py` now writes a seeded sample of each
object family in full plus exact integer and `fsum` totals over every row, and `store-check.ts`
recomputes both (176 MB of JSON, `--sample 40`). It takes `--anchor` (the collection, as the app's
`VITE_COLLECTION_OF`) and `--gwas`, and `--smoke-genes`/`--smoke-variants` so the trans smoke suite
has SMARCB1's, MICAL3's and rs4819361's frames to compare against. The three smoke suites read the
per-scan documents from `store.json` and carry the genome-wide numbers: PDXK 115 eQTL and 404 sQTL
trans rows (two trans requests on open, one per trans object), MICAL3 5,436 and 69, SMARCB1 895
and 933, rs34599497 one trans row and eight hits requests (a table and a frame per QTL experiment;
rs457868 seven, its eQTL cis frame being empty), Home 10,220 eGenes / 13,540 introns / 19,423
genes / 22 coloc loci, About 12,494,731 GWAS variants and 15,824,574 trans pairs. The cis CSV
header is `beta, beta_se`. `chr1:1000000` as the "chromosome not held" case became `chrY:1000000`.
The `v1-*` bench pages are renamed `v2-*` with SMARCB1's ready count at 895; the FLNC/HHATL trans
entries keep their live-store counts, which the genome-wide build should reproduce.
